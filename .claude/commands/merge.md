PR을 merge하고 CLAUDE.md까지 갱신해줘.

## 1. merge 전 확인

- PR의 **head 커밋 sha가 방금 push한 것과 같은지** 확인할 것
  (push 직후 곧바로 merge하면 마지막 커밋이 빠질 수 있음 — 실제로 한 번 겪음)
- `mergeable_state`가 `clean`인지 확인
- **squash merge**로 진행

merge 후 `unsubscribe_pr_activity`로 구독 해제하고, 예약해둔 자체 점검이 있으면 중단할 것.

## 2. CLAUDE.md 갱신

`git fetch origin main` → `main`으로 이동 → `git reset --hard origin/main`으로 맞춘 뒤 작성.

**맨 위 세션 기록에 새 항목을 추가**한다(최신이 위로, 이전 차수는 그 아래로 밀림).
읽는 사람은 **다음 세션의 나 자신**이라는 전제로, 저장소만 보면 알 수 없는 것을 남길 것:

- 무엇을 왜 그렇게 정했는지 — 특히 **되돌리면 안 되는 결정**은 🔴로 이유까지
- 지시서와 다르게 판단한 것과 그 근거
- 지시서가 예상하지 못했던 실제 구조 (예상과 달랐던 것)
- ⚠️ **사용자가 코드 밖에서 해야 하는 일** (DB 마이그레이션, 외부 서비스 등록 등)
- **아직 없는 것 / 일부러 안 한 것** — 다음 세션이 "왜 안 되어 있지" 하고 헤매지 않게
- 실사용 리뷰 라운드가 있었으면 **지적 내용과 반영 이유**도 함께
- 검증 방법과 기준선 수치

그리고 아래도 같이 손볼 것:

- **로드맵**: 끝난 차수를 `~~취소선~~ — N차 세션에서 완료`로 바꾸고,
  다음 차수 번호를 밀 것. "이후 세션이 알아야 할 것만 요약"도 몇 줄 남길 것
- **낡아진 항목 정리**: 이번 작업으로 해소된 "별도 세션 과제"·"범위 밖" 항목이 있으면
  그대로 두지 말고 해소됐다고 갱신할 것

## 3. main에 바로 반영

CLAUDE.md만 바뀐 커밋은 **PR을 만들지 않고 `main`에 바로 commit + push**한다
(31차에 사용자가 정한 규칙 — 배포에 영향이 없는 문서 변경이라 매번 확인받는 게 번거로움).

⚠️ **코드가 한 줄이라도 섞여 있으면 이 규칙은 적용되지 않는다** — 그때는 PR을 만들 것.

## 4. 마지막으로

사용자에게 보고할 것:
- merge된 커밋과 CLAUDE.md 커밋
- CLAUDE.md에 남긴 핵심 (특히 다음에 되돌리면 안 되는 것)
- **남은 작업** — 사용자가 직접 해야 하는 것, 다음 차수 착수 전 정해야 하는 것
