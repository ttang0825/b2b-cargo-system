```
     `React.memo` + **값만 넘기기** + `useCallback` **셋이 한 벌**이다(하나만 어겨도 무력).
     159 → 99ms. 레이아웃은 카드에 `padding` 이 아예 없던 것(구획 제목이 가장자리에 붙음)
  2  「여전히 버벅이고 **윈도우도 같이 버벅댄다**」
     🔴 **1라운드 진단이 일부였다. 「윈도우도」가 결정적 단서였다** — 메인 스레드가 오래 잡힌다는 뜻.
     🔴 **내 미리보기에 화주 목록이 없었다.** 실제 화면은 등록 폼과 목록이 같은 컴포넌트에
     있고 화주가 **540건**인데 페이지네이션이 없다. 폼 높이가 바뀔 때마다 그 아래 수천 DOM 이
     다시 배치됐다. 목록 카드에 `contain: layout style` + 폼이 열리면 목록·검색·탭을 안 그림.
     DOM **3,819 → 408** · 평균 **64ms**(반복 30~45) · 스로틀 없이 11~20ms.
     ⚠️ 1라운드에 「데스크탑 5~17ms 라 괜찮다」고 보고한 것은 **목록 없는 화면을 잰 값**이라 틀렸다
  3  🔴 **「신규업체등록을 누르면 아무것도 안 뜬다」 — 2라운드 수정이 만든 회귀.**
     목록·검색·탭을 `{!showForm && (…)}` 로 감싸면서 **그 괄호 안에 등록 폼 블록까지** 넣었다.
     두 조건이 배타적이라 **폼이 영영 렌더링될 수 없었다.** 폼을 래퍼 **바깥 앞쪽**으로 옮기고
     조회 실패 배너도 바깥으로 뺐다(안에 있으면 폼이 열린 동안 오류가 안 보인다)
  4  「대시보드에 수만 나오는데 클릭시 명단이 나오면 좋겠다」
     숫자를 눌러 펼치는 명단 + 이름 → 화주 상세(`next/link`, 원칙 31번) + 종료일 병기.
     🔴 **API 가 개수를 따로 주지 않는다 — 명단 길이가 곧 개수다**(두 값을 나눠 보내면
     「3개인데 명단은 2줄」로 조용히 어긋난다). 0개·조회 실패일 때는 **버튼으로 만들지 않는다**
     (눌러도 아무 일이 없으면 고장으로 읽힌다)
```
