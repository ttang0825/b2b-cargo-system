🔴 **라보 `400km 초과` = 256,000 이다.** `285,000 × 0.90 = 256,500` 이라 반올림 방식에 따라
**256,000 / 257,000** 으로 갈린다 — 마이그레이션 ⑥ 단언이 256,000 을 못박는다.
**`round(one_ton * 0.90, -3)` 같은 SQL 로 생성하면 그 한 칸이 어긋난다.**
⚠️ 계수는 값이 어떻게 나왔는지를 설명할 뿐 **계산식이 아니다**(다마스 0.849~0.904 ·
라보 0.875~0.952 로 구간마다 다르다).
🔴 **10km → 20km 의 +32%/+31% 급등은 정상이다** — 1톤의 같은 칸이 +30%(40,000 → 52,000)라
그대로 물려받은 모양이고 원인은 **1톤 10km 40,000 정책 고정값**이다. 「펴자」고 하지 말 것.

**═══ ⑩ 🔴 되돌리면 안 되는 구현 지점 ═══**
- 🔴 **재설정 API 는 서버에서 `role === 'admin'` 을 다시 확인한다**(원칙 25번). 화면에서
  버튼을 숨기는 것만으로는 콘솔에서 직접 부르는 것을 못 막는다. **대상이 실제 직원
  계정인지도 확인한다** — 안 하면 화주포털 계정 비밀번호까지 바꿀 수 있다.
- 🔴 **재설정은 비밀번호와 `must_change_password` 를 `updateUserById` **한 호출로** 함께
  바꾼다.** 따로 돌다 한쪽만 성공하면 「임시 비밀번호인데 아무 화면이나 들어가지는」
  상태가 생긴다. ⚠️ `updateUserById` 는 `user_metadata` 를 **병합이 아니라 교체**하므로
  `role`·`status` 미러링을 되살리는 보정이 뒤따른다 — 그 블록을 지우지 말 것.
- 🔴 **middleware 의 강제변경 검사는 재직 확인 *뒤*에 있다.** 앞에 두면 퇴사자가 차단
  대신 변경 화면으로 간다. 판정은 `user_metadata.must_change_password === true` 이고
  값이 없으면 막지 않는다(켜는 곳이 재설정 API 한 곳뿐이라 그게 맞다).
- 🔴 **`/admin/change-password` 라우트를 지우지 말 것** — middleware 가 여기로 보내는데
  화면이 없으면 404 에 갇힌다. **`PUBLIC_PATHS` 에 넣지도 말 것**(로그인이 필요한 화면).
  `PUBLIC_PATHS` 3개는 그대로다.
- 🔴 **해제는 클라이언트가 직접 안 한다** — `/api/admin/confirm-password-change` 가 토큰을
  **서버에서 직접 검증**한 뒤 끈다(원칙 30번. 화주쪽과 같은 구조, **표는 다르다**).
  DB 와 `user_metadata` 를 **둘 다** 끈다 — 한쪽만 끄면 계속 되돌아온다.
- 🔴 **판별자를 `kind: "ok"|"failed"|"locked"` 문자열로 뒀다** — 이 저장소는 `strict: false`
  라 `if (!result.ok)` 로는 타입이 **안 좁혀진다**(실제로 컴파일 에러가 났다). boolean
  판별자로 되돌리지 말 것.
- ⚠️ **`.ilike("login_id", id)` 를 쓴다** — supabase-js 에 `lower(col) = ?` 를 거는 방법이
  없다. `_`·`%` 가 와일드카드가 되지만 `LOGIN_ID_PATTERN` 이 그 앞에서 이미 걸러낸다.
  **패턴 검사를 빼면 이 자리가 구멍이 된다.**
- 🔴 **성공 경로에서 `setLoading(false)` 를 부르지 않는다**(PR #129 와 같은 이유).
  로그인 화면의 `LEGACY_SAVED_EMAIL_KEY` 제거도 지우지 말 것 — 옛 키에는 **이메일**이
  들어 있어서 그대로 읽으면 아이디 칸에 이메일이 채워진다.
