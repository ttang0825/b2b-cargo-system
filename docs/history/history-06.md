**═══ ① 🔴 「움직인다」의 원인은 `100vh` 다 — 두 화면 공통 ═══**
착수 전에 먼저 쟀더니 **원인이 하나가 아니었다.** 이 실측이 방향을 갈랐다.
```
                  390x844      390x667
  /admin/login    넘침 0px      0px      ← 내용이 딱 맞는데도 움직인다고 했다
  /customer/login 넘침 472px    649px
```
🔴 **내부관리가 넘침 0인데도 움직이므로, 두 화면 공통 원인은 내용 높이가 아니다.**
**모바일 브라우저의 `100vh` 는 「주소창이 숨겨졌을 때의 큰 높이」다.** 주소창이 보이는
처음 상태에서는 화면이 그만큼 넘쳐 스크롤이 생기고 → 조금 스크롤하면 주소창이 접히고 →
화면이 늘어나고 → 다시 튕겨 올라온다. 이것이 「확장되서 움직인다」의 정체다.
🟢 `app/globals.css` 에 **`.screen-fit`**(`min-height: 100vh` 폴백 + `min-height: 100dvh`)
을 만들어 `/admin/login` · `/customer/login` · `/customer/support-verify` 셋에 걸었다.
`100dvh` 는 **지금 실제로 보이는 높이**라 넘치지 않는다.
🔴 **두 줄은 한 벌이다** — 위가 `dvh` 를 모르는 옛 브라우저용 폴백이고 아는 브라우저는
뒤의 `dvh` 를 쓴다. 🔴 **인라인 `minHeight: "100vh"` 로 되돌리지 말 것** — 인라인 style 은
같은 속성을 두 번 못 적어서 폴백을 둘 수 없다(그래서 클래스로 뺐다).
⚠️ **Playwright 로는 이 증상이 재현되지 않는다** — 주소창이 없어 `100vh == 보이는 높이`다.
재현이 아니라 **원리와 「내부관리는 넘침 0인데도 움직인다」는 사실**로 특정한 것이다.

**═══ ④ 🔴 카톡 자체 브라우저 — 있지도 않은 메뉴를 안내하고 있었다 ═══**
카톡으로 링크를 열면 **카톡 자체 브라우저(in-app browser)** 가 뜨는데 거기에는

메뉴를 안내하고 있었다.** 사용자가 헷갈린 것이 당연하다.
```
  갈래(맨 앞이 신규)
    🔴 앱 안 브라우저   먼저 기본 브라우저로 넘긴다
    설치 신호를 잡았다   눌러서 바로 설치
    아이폰              「공유 → 홈 화면에 추가」
    크로미움 + 신호 없음 주소창 설치 아이콘 · ⋮ 메뉴
```
🔴 **in-app 판정을 맨 앞에 둘 것** — 뒤로 밀면 iOS·크로미움 갈래가 먼저 걸려 다시 틀린
안내가 나간다. 🔴 **카톡은 `kakaotalk://web/openExternal?url=` 로 넘긴다** — 카톡이 공식
지원하는 주소라 "사파리로 다시 여세요"라는 설명 대신 **버튼 하나**로 끝난다.
🔴 **다른 앱(네이버·라인·인스타/페북)에는 그런 표준이 없다** — 자동으로 넘기려 하지 말고
**주소 복사 + 메뉴 위치 안내**로 둘 것. 🔴 **페이지를 열자마자 자동으로 넘기지 말 것**
(다른 앱으로 튕기는 것은 사용자가 누를 때만 해야 한다).
⚠️ **UA 문자열은 앱이 갱신되면 바뀔 수 있다** — 못 알아봐도 **화면이 깨지지는 않고**
예전처럼 사파리·크롬 안내로 떨어진다. 새 앱을 겪으면 `detectInApp()` 에 더할 것.
🟢 **주소 복사는 클립보드 API 실패 시 옛 방식(`execCommand`)으로 한 번 더 시도한다** —
앱 안 브라우저는 클립보드 권한이 막혀 있기도 하다.

**═══ ① 🔴 구역에 끝 슬래시를 붙이면 안 된다 — 이번 결함의 뿌리 ═══**
사용자 신고: *"PC 크롬에서 앱 창 위에 주소 띠가 남는다."*
```
  manifest 의 scope · start_url    "/admin/"
  실제 홈 주소                      "/admin"    ← Next 가 "/admin/" 을 308 로 여기로 보낸다
```
🔴 **구역 판정은 문자열 접두 비교라 `/admin` 은 `/admin/` 안에 들어가지 않는다.**
그래서 **앱이 켜지자마자 자기 구역 밖으로 나갔고** 크롬이 첫 화면부터 주소 띠를 세웠다.
🔴 **`scope`·`start_url` 을 `/admin`·`/customer` 로 둘 것 — 끝 슬래시를 다시 붙이지 말 것.**
⚠️ **`.webmanifest` 는 JSON 이라 주석을 못 단다** — 사유를 `app/{customer,admin}/layout.tsx`
의 `manifest:` 옆에 적어 뒀다. 그 주석을 지우면 다음 사람이 같은 실수를 한다.
🟢 **`id` 는 `/admin/`·`/customer/` 그대로 뒀다** — 앱의 정체성이라 바꾸면 **이미 설치된
앱이 고아가 되어 자동 갱신을 못 받는다.** `id` 는 구역 안에 있을 필요가 없다.
⚠️ **`trailingSlash: true` 로 우회하지 말 것** — 사이트 전체 URL 규칙이 바뀐다.
⚠️ **`start_url` 을 `/admin/login` 으로 돌려 피하지도 말 것** — 로그인한 사람이 홈(`/admin`)
으로 가는 순간 다시 구역 밖이 된다. **구역 자체를 고치는 것이 유일한 해법이다.**

**═══ ② 🔴 같은 이유로 홈에서는 오프라인 안내가 안 떴다 ═══**
서비스워커의 기본 구역도 스크립트가 놓인 폴더(`/admin/`)라 **시작 화면인 `/admin` 을 맡지
못했다.** 즉 PR #126 의 「오프라인 안내」가 **하위 화면에서만** 동작하고 있었다(내 검증이
`/admin/login` 만 봐서 못 잡았다).
🔴 **스크립트 위치보다 넓은 구역은 서버가 허락해야 한다** — `next.config.mjs` 의
`headers()` 가 `Service-Worker-Allowed: /admin` 을 붙이고, 등록할 때
`register(url, { scope: "/admin" })` 을 넘긴다.
🔴 **둘은 한 벌이다 — 한쪽만 고치면 등록이 조용히 실패한다**(예외도 안 난다).
🔴 **여기서 구역을 더 넓히지 말 것**(`/` 로 넓히면 한 워커가 두 앱과 랜딩을 삼킨다).
🟢 **옛 구역(`/admin/`)으로 등록돼 있던 워커는 등록 직후 정리한다** — 내 세그먼트 안의
것만 건드린다(다른 앱의 등록을 지우면 안 된다). 안 지우면 둘이 같이 남는다.

**═══ ③ 🔴 설치 신호를 하이드레이션 뒤에 들으면 놓친다 ═══**
사용자 신고: *"설치했다 지운 뒤로 「앱으로 설치」 버튼이 안 보인다."* 원인이 둘이었다.
**(a) 신호를 늦게 듣고 있었다.** 크롬은 `beforeinstallprompt` 를 화면이 뜨자마자 **한 번만**
쏘는데 `useEffect` 에서 듣기 시작하면 그 사이에 지나간 신호를 영영 못 받는다. 화면이
무거울수록 잘 놓쳐서 **「어떤 날은 뜨고 어떤 날은 안 뜬다」**로 나타난다.
🔴 **`lib/installPromptCapture.ts` 의 인라인 스크립트가 HTML 을 읽는 순간 먼저 잡아
`window.__wcInstall` 에 넣고, 버튼은 그것을 읽는다. 이 스크립트를 지우거나 아래로 옮기지
말 것.** `preventDefault()` 도 빼지 말 것(브라우저 자체 배너가 겹친다).
**(b) 크롬은 앱을 지운 뒤 한동안 신호를 아예 다시 쏘지 않는다.** 그때도 주소창 설치
아이콘으로는 설치가 되는데 **버튼이 사라져서 다시 설치할 길이 없었다 — 사용자가 실제로
막힌 자리다.**
🔴 **그래서 갈래가 셋이 됐다. 「크로미움인데 신호가 없다」 갈래를 지우지 말 것:**
```
  신호를 잡았다            눌러서 즉시 설치
  아이폰                   「공유 → 홈 화면에 추가」 안내
  🔴 크로미움 + 신호 없음   주소창 설치 아이콘 · ⋮ 메뉴 경로 안내(안드로이드는 「앱 설치」)
  그 밖 / 이미 설치됨      안 그림
```
🟢 **셋 다 눌러서 뭔가 되므로 「누를 수 없는 버튼은 만들지 않는다」는 원칙은 그대로다.**
⚠️ **「크로미움인데 신호가 없다」가 늘 「지운 직후라서」인 것은 아니다** — PR #130 에서
**서비스워커가 그 화면을 안 맡아서** 신호가 아예 안 오던 경우가 나왔다(랜딩에서
클라이언트 전환으로 들어온 문서). **안내창이 뜬다는 신고를 받으면 `controller` 부터 볼 것.**
🔴 **크로미움 판정은 UA 가 아니라 `"onbeforeinstallprompt" in window` 다** — 사파리·
파이어폭스는 이 속성이 없다. UA 문자열로 바꾸지 말 것.
⚠️ 안내 창은 여전히 자기 글자색·정렬을 인라인으로 선언한다(65차 ⑤ · 66차 ⑯-3).
